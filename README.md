# Gen-Can（現場管理アプリ）

小規模の電気工事・建設会社向けの現場管理PWAです。現場管理・作業日報・タイムカード・工事写真（小黒板カメラ／台帳）・スケジュール・工程表・材料/車両/道具管理・AIツールをひとつにまとめています。

## 仕組み

```
スマホ/PCのブラウザ（このリポジトリの静的HTML。GitHub Pages等で配信）
        │  JSONP / POST
        ▼
Google Apps Script（Code_vXXX.gs。認証とデータ処理）
        │
        ▼
Googleスプレッドシート（データ） ＋ Googleドライブ（ファイル・写真）
```

- サーバー不要。データはすべて**利用会社自身のGoogleアカウント**内に保存されます。
- GASのソースコード（Code_vXXX.gs）はこのリポジトリには含まれません（Apps Script側で管理）。

## 設定ファイル（config.js）

バージョンと販売先ごとの設定は **config.js で一元管理**します。

| 項目 | 内容 |
|---|---|
| `APP_VERSION` / `BUILD` | アプリのバージョン。**ファイルを更新したら必ず変更**（全ページのバッジに反映） |
| `EDITION` | **自社用／販売用の切替**。`'vendor'`=自社用（全ページ表示）／`'customer'`=販売用（自社専用ページを非表示） |
| `VENDOR_PAGES` | 販売用で隠す自社専用ページ一覧（通常は変更不要） |
| `GAS_URL` | Google Apps Script のデプロイURL |
| `COMPANY_NAME` / `COMPANY_SHORT` | 会社名（帳票・画面表示に使用） |
| `WEATHER_LAT` / `WEATHER_LON` / `WEATHER_PLACE` | 天気予報の地点 |
| `GAS_FILE` | 使用中のGASファイル名（診断画面が照合に使用） |

### 自社用 / 販売用エディション（EDITION）

同じコードベースで、開発元（自社）用と販売先（お客様）用を切り替えられます。

- **`EDITION: 'vendor'`（自社用）**：全ページ表示。ログイン画面に「自社用モード」の目印が出ます。販売元（自社）の日常利用はこちら。
- **`EDITION: 'customer'`（販売用）**：`VENDOR_PAGES` に挙げた自社専用ページ（料金メモ `sales`、営業デモ `demo`、規約たたき台 `legal`、導入/最終チェック `rollout`/`finalcheck`、運用センター `operations`、更新手順 `update`、診断 `diagnosis`、バックアップ `backup`）を**ホーム・各画面のリンクから隠し、直リンクで開いてもブロック画面**を表示します。ログインのデモボタンも消えます。

**販売先へ納品するときは `EDITION: 'customer'` に変更**してから配信してください（他の `COMPANY_*` 等と一緒に config.js を書き換えるだけです）。

## 販売先への納品手順（新規セットアップ）

1. **Googleアカウント**：納品先のGoogleアカウント（またはGoogle Workspace）を用意
2. **GAS**：Apps Scriptで新規プロジェクトを作成し、最新の `Code_vXXX.gs` を貼り付け →「デプロイ」→「ウェブアプリ」→ アクセス「全員」でデプロイし、URLを控える
3. **シート・フォルダ**：アプリの `setup/`（初期設定）画面から不足シート・Drive親フォルダ・台帳テンプレートを自動作成
4. **このリポジトリを複製**して納品先用のGitHub Pages（または任意のホスティング）を用意
5. **config.js を書き換え**：`GAS_URL`・`COMPANY_NAME`・`COMPANY_SHORT`・`WEATHER_LAT/LON/PLACE` を納品先の値に
   - ⚠️ **販売元の会社名とGAS URLが入っているのは config.js のこの数行だけです（v43.19.0で全ページから直書きを撤去済み）。納品前に必ずここを納品先の値へ書き換えてください。** 販売元のGAS URLのまま納品すると、納品先のアプリが販売元の業務データに接続してしまいます
6. **別ドメイン／別リポジトリ名で配信する場合のみ**：`manifest.json` の `start_url` と `scope`（現在 `/genba-projects/`）を配信パスに合わせて変更
7. **作業員登録**：`admin/`（管理画面）で作業員・ログインID・権限を登録
8. **確認**：`rollout/`（導入チェック）と `finalcheck/`（最終チェック）を実行し、全項目OKを確認

## 既存環境への更新手順

1. 更新ファイルをGitHubへアップロード（config.js の APP_VERSION/BUILD 更新を忘れずに）
2. GAS側の変更がある場合：Code_vXXX.gs を貼り替え →「デプロイを管理」→ 既存デプロイを**新バージョンで更新**（保存だけでは反映されません）
3. ブラウザで強制再読み込み（Ctrl+F5）。アプリ内 `update/` 画面に手順とチェックリストがあります

## 運用・保守ページ

| ページ | 用途 |
|---|---|
| `operations/` | 運用センター（各種チェックの入口） |
| `diagnosis/` | エラー診断 |
| `backup/` | バックアップ状態確認 |
| `version/` | 顧客向け更新履歴 |
| `support/` | 不具合報告（端末情報の自動収集） |
| `demo/` | 営業説明用デモ（実データに接続しない） |

## 販売前の必須確認

- **特定商取引法に基づく表示**：`sales/`（販売設定）に運営責任者・所在地・電話番号・支払方法・解約条件を記入し、`legal/` のたたき台を完成させて公開すること（有料販売では法定義務）
- **パスワード保護**：GAS v157で実装済みを確認済み（詳細は `GAS変更指示書_v43.10.1.md` の確認結果を参照。追加作業は不要）
- オフライン時はデータの閲覧・保存はできません（案内ページのみ表示されます）。製品説明に明記してください
